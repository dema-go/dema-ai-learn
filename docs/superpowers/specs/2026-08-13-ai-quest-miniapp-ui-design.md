# 「考我一下」AI 闯关学习小程序 HTML 原型设计规范

> 日期：2026-08-13  
> 状态：待用户书面复核  
> 输入依据：`需求分析.md`、`技术方案.md`、`竞品调研资料.md`、`UI竞品设计调研.md` 及本轮草图评审结论

## 1. 产品定义

「考我一下」是一款面向成年泛知识自学者的微信小程序。用户粘贴刚读过的中文内容或公开网页链接，AI 只依据该材料生成 5–7 道单选与判断题。用户约 3 分钟完成一关，每题均可查看原文依据，完成后可立即复测错题。

核心口号：**把刚读的，考明白。**

本原型的首要任务不是呈现一个庞大的学习平台，而是验证一条短闭环：

`提交材料 → 等待生成与校验 → 完成闯关 → 查看原文依据 → 复测错题 → 再次创建`

## 2. 已确认的产品决策

### 2.1 用户识别

- 首次打开即由系统静默识别 `openid`，不展示登录阻断页。
- 昵称、头像与订阅提醒仅在功能确实需要时请求显式授权。
- 用户可跳过昵称与头像授权，不影响创建、答题、查看结果和复测。

### 2.2 输入范围

- MVP 可用：粘贴文本、公开网页链接。
- 粘贴文本上限为 8,000 中文字，超限时明确要求用户裁剪，不静默截断。
- 网页链接只支持无需登录、无需付费、无需验证码的公开页面。
- 拍照、PDF、Word、PPT 入口在原型中展示，但必须灰化并标注“敬请期待”；点击后只显示能力说明，不进入虚假流程。

### 2.3 首页结构

采用“任务优先型”首页：

1. 有待复测错题时，主卡为“错题翻盘”。
2. 没有待复测但存在未完成闯关时，主卡为“继续闯关”。
3. 以上均不存在时，主卡为“把材料变成闯关”。
4. 主卡下展示最近闯关和新建入口。
5. 首次用户直接看到一屏内的产品价值说明与新建入口，不单独设置多页 onboarding。

### 2.4 游戏化边界

- MVP 使用连续天数、星星、进度、完成印章和错题翻盘反馈。
- 不使用生命值、金币、钻石、排行榜、多人 PK 或分享解锁。
- 单次闯关内部可使用轻量关卡节点，但首页不采用纵向大地图。
- 错误不会阻断学习，也不会触发角色羞辱或惩罚性文案。

## 3. 品牌与原创角色

### 3.1 临时品牌

- 产品名：**考我一下**
- 口号：**把刚读的，考明白**
- 传播语气：“你说看完了？那我可要出题了。”
- 正式上线前必须另行核验商标、小程序名称及域名可用性。本规范仅确定原型阶段名称。

### 3.2 角色“考考”

“考考”是原创的学习翻车搭档，不是老师或权威裁判。它承担四项职责：

1. 在首页和首次引导中说明产品价值。
2. 在生成等待中解释当前阶段，减轻等待焦虑。
3. 在正误反馈和空状态中提供夸张但友好的情绪反应。
4. 在原文依据和纠错场景中提醒用户：AI 题目可能有误，可以核查与反馈。

角色使用内联 SVG 绘制，基础特征为黄色圆头、薄荷青上衣、粗线轮廓和夸张眉眼。不同状态通过眼睛、嘴形、手势、汗滴、星星与纸张道具变化。不得复制《阿衰》的角色外形、服装、姓名、标志性构图、台词或封面字体。

## 4. 视觉系统

### 4.1 视觉定位

已确认采用“爆笑练习册”方向，并允许卡通表达更大胆。整体通过练习本、批注、印章、拟声词与角色小剧场唤起成年人对校园漫画的怀旧感，但阅读区必须像现代移动产品一样清晰。

视觉原则：**界面负责阅读，SVG 负责卡通。**

### 4.2 色彩令牌

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 暖纸底 | `#FBF7EE` | 小程序主背景 |
| 纯纸白 | `#FFFEFA` | 内容卡、答题卡、弹层 |
| 珊瑚红 | `#DE5848` | 主按钮、当前状态、关键批注 |
| 珊瑚浅色 | `#FBE2DD` | 红色标签和提示底色 |
| 薄荷青 | `#78CDBF` | 正确反馈、角色服装、完成状态 |
| 薄荷浅色 | `#D9F0EB` | 正确提示和辅助卡背景 |
| 奖励黄 | `#FFD45A` | 星星、印章、稀疏强调 |
| 正文深灰 | `#24292D` | 标题与正文 |
| 次要文字 | `#6F777E` | 辅助说明、时间与元数据 |
| 边界灰 | `#D8D4CB` | 卡片边线、分隔线 |
| 错误红 | `#C9443A` | 明确错误文本与错误图标 |

约束：

- 珊瑚红不用于大面积背景；单屏高饱和色面积控制在约 20% 以内。
- 奖励黄只用于奖励、贴纸和少量角色部位，不承担正文背景。
- 正误不能只靠红绿区分，必须同时显示图标、文字和边框变化。
- 页面画廊与实际手机画板都使用浅色背景，不再使用大面积深灰评审底色。

### 4.3 字体与排版

- 中文字体栈：`PingFang SC`, `Microsoft YaHei`, `Noto Sans SC`, sans-serif。
- 不使用楷体、仿宋或手写字体承载标题、题干、正文、选项和按钮。
- 页面大标题：28–32 px，700–800 字重，行高 1.2。
- 手机画板一级标题：24–28 px，700–800 字重，行高 1.2。
- 题干：18–20 px，600–700 字重，行高 1.55。
- 正文与选项：15–17 px，400–600 字重，行高 1.55–1.7。
- 辅助信息不得小于 12 px；重要合规说明不得小于 13 px。
- 手写感仅通过 SVG 批注、印章和拟声词实现，不引入影响阅读的字体依赖。

### 4.4 组件形态

- 内容卡采用 14–20 px 圆角、1–1.5 px 边线和轻量暖色投影。
- 只有角色贴纸、印章和装饰纸片允许轻微旋转；按钮、表单、选项与正文卡保持水平。
- 主按钮高度不低于 48 px，选项最小高度不低于 52 px。
- 主按钮使用珊瑚红；正确反馈按钮可使用薄荷青；危险删除操作使用描边错误红。
- 页面仅保留一个视觉主行动，次级行动使用文字或浅色按钮。

## 5. 信息架构与原型文件

最终交付为三份独立 HTML 文件。每份文件桌面端按一行三列显示手机画板，窄屏自动变为两列或一列。每个画板宽度约 360–390 px，展示接近微信小程序的完整纵向页面。

### 5.1 `core-flow.html`：核心业务流程

包含 12 组画板：

1. 首次首页：静默识别、一屏引导、新建闯关。
2. 回访首页：错题复测优先、续答、最近闯关。
3. 选择输入：文本和 URL 可用；拍照、PDF、Word、PPT 标注“敬请期待”。
4. 粘贴文本：实时字数、8,000 字限制、隐私与机密信息提醒。
5. 网页链接：公开网页说明、链接校验与正文预览。
6. 生成等待：理解原文、抓重点、生成题目、校验答案四阶段；可离开。
7. 生成结果预览：材料标题、题量、题型、限源声明和“开始闯关”。
8. 逐题作答：单题单屏、大选项、进度、AI 标识。
9. 答对反馈：原位正确状态、简短解释、原文依据入口。
10. 答错反馈：正确答案、错因、原文依据入口，不羞辱用户。
11. 一键纠错：无依据、答案错、有歧义、太简单。
12. 通关结果与错题复测：正确率、用时、错题列表、复测入口和翻盘完成状态。

关键状态以切换控件或同画板变体呈现：空内容、超长文本、URL 抓取失败、登录墙、内容安全拦截、生成降级、生成超时/失败和中断续答。

### 5.2 `records-share.html`：记录、复用与分享

包含 9 组画板：

1. 最近闯关列表：全部、进行中、待复测筛选。
2. 闯关记录详情：成绩、题目记录、来源信息和删除入口。
3. 错题本：按材料分组并直接开始复测。
4. 结果卡预览：只展示主题、成绩、用时和品牌，不包含全文。
5. 分享落地页：成绩与一道预览题，适配微信单页模式。
6. 被分享者挑战：挑战同一关或创建自己的闯关。
7. 订阅提醒授权：通关后按需请求，可拒绝。
8. 次日复测召回：进入三道错题的短回合。
9. 免费额度触顶：每日三次、次日恢复，不展示未确定的复杂付费方案。

关键状态：历史为空、无错题、材料已过期和分享失败。

### 5.3 `settings-future.html`：个人、合规与扩展

包含 10 组画板：

1. 我的：匿名头像、连续天数、星星和闯关统计。
2. 按需完善资料：昵称与头像显式授权，可跳过。
3. 隐私与数据：材料保留期、主动删除和敏感信息说明。
4. 删除确认：影响说明、二次确认和删除成功反馈。
5. 帮助与问题反馈：版权投诉、题目质量和联系入口。
6. 拍照导入，标注“敬请期待”。
7. PDF、Word、PPT 文件导入，标注“敬请期待”。
8. 题量与难度设置，标注“敬请期待”。
9. 间隔复习计划，标注“敬请期待”。
10. 成就贴纸册，标注“敬请期待”。

明确不画：多人 PK、排行榜、知识库 RAG、视频音频、复杂 VIP 和企业后台。

## 6. 核心交互与数据呈现

### 6.1 生成等待

- 前端以任务轮询为交互模型，不模拟流式文字生成。
- 阶段文案依次为“正在理解原文”“正在抓住重点”“正在生成第 N 题”“正在检查答案”。
- 用户可返回首页；首页任务卡继续显示后台状态。
- 生成降级但仍有可用题时，提示“这篇材料只适合出 5 题，考考不硬凑”，并允许正常开局。
- 完全失败时给出可行动原因：裁剪文本、改用粘贴、重新尝试或换一份材料。

### 6.2 作答与即时反馈

- 选择答案后，用户主动点击“确定答案”；避免误触即提交。
- 提交后在当前页面原位切换反馈，不跳转到另一个信息密集页面。
- 解析默认 1–3 行；原文依据以折叠区或底部抽屉展开。
- 原文依据突出显示最短支持片段，不展示整篇材料。
- “这题有问题”始终可触达，但视觉等级低于“下一题”。

### 6.3 通关与复测

- 结果页先庆祝完成，再展示正确率、用时和错题。
- 不使用“你已掌握”或“你已学会”等不可证实表述。
- 有错题时，主按钮为“马上翻盘”；无错题时，主按钮为“再考一篇”。
- 分享为次级操作，不提供奖励，不与答案、下一关或额度绑定。

## 7. 完整状态与错误处理

| 场景 | 用户文案目标 | 主行动 |
| --- | --- | --- |
| 文本为空 | 说明至少需要一段可出题内容 | 返回输入 |
| 超过 8,000 字 | 明确未被静默截断，建议保留重点 | 继续裁剪 |
| 网页需登录或付费 | 不尝试绕过限制 | 改用粘贴文本 |
| 网页内容过短 | 说明材料不足以生成可靠题目 | 换链接或粘贴全文 |
| 内容安全未通过 | 简洁说明不可处理，不展示敏感详情 | 修改内容 |
| 生成超时 | 任务可继续查询，不要求重复提交 | 稍后查看或重试 |
| 生成完全失败 | 说明没有凑题 | 调整材料 |
| 题量降级 | 说明只生成了可信题目 | 开始现有题目 |
| 历史为空 | 解释记录会出现在哪里 | 创建第一关 |
| 无错题 | 祝贺并引导新材料 | 再考一篇 |
| 免费额度触顶 | 说明恢复时间 | 明天再来 |

## 8. 动效与可访问性

- 主要动效时长 180–350 ms；通关盖章可放宽到 600 ms。
- 答对：卡片轻弹、薄荷青描边、星星飞入。
- 答错：选项轻微水平抖动、错误图标和考考冒汗，不使用强烈震屏。
- 生成等待：SVG 角色翻页、批改或举牌，阶段切换明确。
- 支持 `prefers-reduced-motion`，关闭位移和循环动效，仅保留颜色与文字变化。
- 所有交互支持键盘焦点，焦点环可见；按钮使用语义元素。
- 文本与背景遵循 WCAG AA 对比目标；SVG 装饰图设置无障碍隐藏，承载信息的 SVG 提供标签。

## 9. HTML 原型交付标准

- 三份 HTML 可直接双击或通过本地静态服务器打开，不依赖构建工具。
- 公共视觉令牌与组件样式可放入一个共享 CSS；公共交互可放入一个共享 JavaScript 文件。
- 不调用真实 AI、微信授权、订阅消息、抓取接口或数据库。
- 使用本地模拟数据和受控计时器演示生成阶段，不自动发起网络请求。
- 页面顶部提供文件内导航和状态切换；画板内关键按钮可演示弹层、表单校验、答案反馈和页面切换。
- 响应式布局：大屏三列、中屏两列、小屏一列；手机画板内部保持 360–390 px 设计比例。
- 原创角色优先使用内联 SVG，避免外链图像失效和版权风险。

## 10. 验收标准

1. 三份文件覆盖本规范列出的全部页面与状态，页面分组清晰。
2. 整套原型只使用已确认的暖纸红 × 薄荷青视觉系统，不出现旧版深灰画布和楷体标题。
3. 首屏主行动符合任务优先级，首次和回访状态可明确区分。
4. 文本与 URL 是唯一可用输入；拍照和文件始终明确标注“敬请期待”。
5. 每道题均展示或可展开原文依据与 AI 生成提示。
6. 答题、正误反馈、纠错、结果和错题复测构成可演示闭环。
7. 生成等待与所有高风险失败场景均有明确、可行动的状态。
8. 分享不展示原文全文，不与奖励或解锁绑定。
9. 昵称、头像和订阅提醒仅按需请求，且均可跳过。
10. 桌面三列与移动单列均无横向溢出、遮挡或不可点击元素。

## 11. 范围之外

本轮不实现真实小程序、后端 API、模型调用、网页抽取、内容安全接口、微信分享、订阅消息、数据持久化、支付、真实商标注册或生产级埋点。HTML 仅用于完整呈现产品 UI、核心交互与状态设计。
